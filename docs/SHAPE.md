# `shape.json` —— 插件的法阵形状

插件就是一个文件夹：

```
plugin/<名字>/
  plugin.json   清单（必需）
  shape.json    法阵形状（可选；没有就用插件名哈希派生一个）
  bin/<名字>.dll
```

`shape.json` 只被「插件图谱」（`spellbook`）读，删掉它不会有任何副作用——图谱会给那个
插件生成一个确定性的哈希形状。**所有字段都可省略**，省略的走哈希；写了就是定值。

## 1. 一个插件的形状 = 若干层

每层是一条**极坐标闭合曲线**：

```
r(θ) = 半径 · (1 + 振幅 · sin(波瓣 · θ + 自转相位))
```

- 渲染交给 `ShapeSpec::PolygonPath`（96 个采样点，一份点列同时决定渲染 / 命中 / 包围盒）；
- 粗细交给 `StrokeShape`（一半在外、一半在内）；
- 「双层 / 华丽」= 多写一两层；「叠在一起」= 两个插件写同一个 `radius`。

层与层之间只差几个数，所以下面这张表就是全部词汇。

## 2. 顶层

| 键 | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `radius` | 0..1.2 | 自动 | 本插件的**基准半径**，相对法阵外径。不写则按扇入（被依赖次数）自动分配 |
| `orbit` | 度/秒 | `6` | 整张阵的绕点转速，会被每层的 `orbit` 覆盖 |
| `layers` | 数组 | — | 至少一层；最多读 6 层 |

`radius` 写同一个数就是**重叠**。各层带 `alpha`，重叠处就是半透明叠加（近似"像素和"：
`CanvasContext` 没有加法混合模式，这里是 alpha 混合）。

## 3. 层

| 键 | 类型 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `kind` | 字符串 | `curve` | 图元：`curve` / `ring` / `star` / `polygon` / `spokes` / `path` |
| `radius` | 0..1.2 | 基准半径 | 这一层的绝对半径；不写就用顶层 `radius` |
| `width` | 0.5..40 | 哈希（3..7） | 描边宽（设计像素） |
| `lobes` | 2..24 | 哈希（3..8） | `curve` 的波瓣数；`star`/`polygon` 的边数；`spokes` 的辐条数 |
| `innerRatio` | 0.05..0.98 | `0.5` | `star` 的内/外半径比；`spokes` 的起点比例 |
| `amplitude` | 0..0.30 | 哈希（0.03..0.08） | 振幅，相对半径的比例（只有 `curve` 用） |
| `phase` | 度 | 哈希 | 形状起始相位 |
| `spin` | 度/秒 | 哈希（±2..11） | **自转**：形状相位自己的漂移 |
| `orbit` | 度/秒 | 顶层 `orbit` | **绕点转**：这一层绕法阵中心的转速 |
| `color` | `"rrggbb"` / `"rrggbbaa"` | 哈希色 | 支持 `#` 前缀 |
| `alpha` | 0..1 | `1` | 只在 `color` 是 6 位时生效 |
| `points` | `[[x,y],…]` | 无 | 只有 `kind: "path"` 用：归一化 -1..1 的顶点表 |
| `marks` | 对象 | 不画 | 沿线复制的小元素（塔齿 / 符文点） |
| `runes` | 对象 | 见下 | `needs` 符印 |

### 图元（`kind`）

六种图元最后都落到**同一份顶点表**上（`ShapeSpec::PolygonPath`），所以描边、命中、
包围盒的行为完全一致——这就是"统一基元"：中线不同，其余一样。

| `kind` | 中线 | 典型用法 |
| --- | --- | --- |
| `curve` | 极坐标波浪圆 | 默认；"花瓣"环 |
| `ring` | 正圆 | 盘边 / 外圈 |
| `star` | N 角星（内外半径交替） | 法阵里的星 |
| `polygon` | 正 N 边形 | 框住星的八边形 |
| `spokes` | 一圈径向线段（不闭合） | 星芒 / 辐条扇 |
| `path` | 自定义点列 | SVG path 的等价物 |

把 `star`（16 角、`innerRatio: 0.9`）叠在 `ring` 上，就是参考图里那种"外圈锯齿符带"
——因为运行时拿不到"沿圆周旋转的文字"，符带用几何近似。

`path` 的点列是**归一化坐标**（-1..1，乘本层半径后贴到画布中心，再按 `orbit` 转）。
所以 `d="M … L … Z"` 这类路径，把顶点拆出来写进来就行。

### `marks`（沿线复制）

| 键 | 缺省 | 说明 |
| --- | --- | --- |
| `count` | `0` | 沿中线复制的份数（0..96） |
| `length` | `0` | `> 0` 画径向短线，`0` 画点 |
| `size` | `3` | 点直径 / 线宽 |
| `offset` | `0` | 相对中线的径向偏移（负 = 往内） |
| `color` / `alpha` | 层色 / `0.55` | |

### `runes`（`needs` 符印）

| 键 | 缺省 | 说明 |
| --- | --- | --- |
| `count` | `-1` | `-1` = 用插件 `needs` 的条数；`0` = 不画；`> 0` = 指定条数 |
| `size` | `4` | 直径 |
| `offset` | `8` | 相对中线的径向偏移 |
| `color` / `alpha` | 哈希色 / `0.9` | |

## 4. 例子

**单层，最简**（只覆盖颜色与转速，几何全走哈希）：

```json
{ "layers": [ { "color": "9380c2", "spin": 3 } ] }
```

**三层，华丽**：

```json
{
  "radius": 0.62,
  "orbit": 5,
  "layers": [
    { "width": 5, "lobes": 6, "amplitude": 0.035, "spin": 3,
      "color": "9380c2", "alpha": 0.95,
      "marks": { "count": 18, "length": 7, "size": 1.2, "color": "6e5aae", "alpha": 0.5 } },
    { "radius": 0.70, "width": 1.6, "lobes": 12, "amplitude": 0.02, "spin": -5,
      "color": "6e5aae", "alpha": 0.6 },
    { "radius": 0.55, "width": 2.4, "lobes": 3, "amplitude": 0.05, "spin": 8,
      "color": "9380c2", "alpha": 0.4, "runes": { "count": 0 } }
  ]
}
```

**叠在一起**（与别的插件同半径，alpha 叠色）：

```json
{ "radius": 0.52, "layers": [ { "width": 9, "lobes": 3, "color": "4aa3df", "alpha": 0.38 } ] }
```

## 5. 约定与边界

- **半径是归一化的**（相对法阵外径），与窗口大小无关；
- 半径范围夹在 `0.02..1.20`，超出就夹住而不是报错；
- 读不到 / 读坏 / `layers` 为空 → 整个文件当没有，退回哈希；
- 形状**不影响命中**：命中按每层一个 `Ring` 带（环带宽度 = 线宽 × 2.2，至少 8px），
  所以点在一层的环带里就算点中那个插件——曲线是旋转对称的，转不转都不影响命中；
- 改 `shape.json` 会重链接（`GoldingPlugin.cmake` 把两份 json 都记进了 `LINK_DEPENDS`），
  所以改完直接重跑就能看到。
